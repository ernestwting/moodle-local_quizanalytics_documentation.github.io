Using STACK q-type Analytics

This plugin is visible to teachers, editing teachers, and managers only, never students, on any course with at least one STACK question added directly to a quiz slot. Reach it either from a course's secondary navigation (an Analytics entry, tucked inside More if the bar is full) or directly from a STACK quiz's own settings menu, which jumps straight to that quiz's Question Analytics. Every page carries a Section: switcher at the top for moving between Quiz Analytics, Question Analytics, and Model Analytics. A video guide to using this plugin can be found here.

4.1 Quiz Analytics

The coursewide view: every STACK quiz in the course, compared side by side. You will see an attempts versus grades scatter plot and aggregated difficulty/response distributions. The Compare attempts against: selector switches which grade type (average, highest, or minimum) the scatter plot uses. Two display toggles apply here and on Question Analytics:

  • Colourblind mode swaps every chart's palette for a colourblind safe set.
  • Anonymise student data replaces every real name and email on screen, and in the PDF, with a stable pseudonym ("Student 1", "Student 2", …). This is purely a display option: it changes nothing about what is computed, persists nowhere, and does not restrict who can see the page. See Chapter 6 for exactly what this does and doesn't protect against.

4.2 Question Analytics

Pick a quiz from the dropdown (defaults to the course's first STACK quiz) to see:

  • Quiz snapshot: attempt counts (finished, in progress, other) and the overall average, read straight from Moodle's own attempt data.
  • Question Response Overview: one chart per question, sized to Moodle's own Facility Index and mean mark (the exact figures Quiz → Results → Statistics reports).
  • Question Review: click into a question to see its expected answer and common response patterns, grouped by which instantiated variant a student actually received, with the question text rendered as genuine HTML.

Solution Process Visualization, comprising PRT transition graphs, network features, response tree distance charts, and cross attempt comparison, is fully implemented but temporarily not offered in the on screen View: selector, pending a redesign. It remains reachable directly at:

local/quizanalytics/questionanalytics.php?id=<courseid>&quizid=<quizid>&view=solutionprocess

4.3 Model Analytics

Use the View: selector to move between the two models. Both ship disabled by default, so until an administrator enables and trains one, what you are looking at is each indicator's live reading, not a trained prediction.

  • Model 1, Student Risk & Behaviour. One row per enrolled student: their current grade status against the course's pass grade, and five behavioural indicators, each shown as a badge (Good, Typical, or Worth a look) with a one line plain English explanation.
  • Model 2, Question & PRT Quality. One row per STACK question, with the quiz it belongs to shown underneath: a pass rate based "needs review" flag, and four indicators.

A flag is a prompt to look, never proof of anything on its own.

4.4 Diagnostics Analytics

Two statistical reports for question authors, not model predictions, since neither has a natural ground truth label to predict against. Not currently in the Section: switcher, but fully functional at:

local/quizanalytics/diagnosticsanalytics.php?id=<courseid>

  • Seed bias: a one way ANOVA across a question's random seeds, checking whether some randomised variants are unfairly harder or easier than others.
  • PRT branch coverage: which of a question's PRT branches have actually been triggered by a real student answer.

4.5 PDF exports

Every view in every section carries a Download PDF button. It rederives the same content server side (this is not a screenshot) into a downloadable, landscape oriented report. Quiz Analytics and Question Analytics embed the same charts you see on screen; Model Analytics and Diagnostics Analytics render the same tables as plain text. The file streams straight from the server to your browser; nothing is stored anywhere in the process.

“Generating in the background”

Large quizzes or courses hand their computation to a background task instead of making you wait on the page. Revisit the same page in a minute or two; the page itself rechecks automatically every 20 seconds. If this message is still showing after a genuinely long wait (fifteen minutes or more), see Section 3.7 of Chapter 3 and flag it to your Moodle administrator.
